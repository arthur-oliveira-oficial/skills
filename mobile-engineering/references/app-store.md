# Xcode, TestFlight and App Store Review

Use this route for a signed iOS app, including a React Native iOS target. A web app installed from Safari follows the PWA route. If packaging web content for the store, evaluate the actual experience under App Review guideline 4.2 before investing in distribution.

## Run on iPhone and archive

1. Open the project's workspace when it uses CocoaPods, otherwise its Xcode project or established workspace. Select the app scheme. Connect and unlock the iPhone, trust the Mac and enable Developer Mode on the device when prompted. In Xcode add the development account and check the target's **Signing & Capabilities**, team, bundle ID and provisioning. Select the physical iPhone as the run destination and use **Product → Run**. Reproduce the main journey on device. A personal team can be sufficient for development on your own devices. Store distribution requires appropriate program membership and account access. [Run on physical devices](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)
2. Check the current upload floor. As checked on 2026-11-22, iOS uploads require Xcode 26 or newer and the iOS 26 SDK or newer. Apple also lists iOS 13 as the minimum deployment target for uploads since September 9, 2026. Record the SDK used to build and the oldest OS the app supports as separate values. [Apple submission requirements](https://developer.apple.com/news/upcoming-requirements/)
3. Match the bundle ID to the App Store Connect app record. Check the marketing version, unique build number for the version, release configuration, signing and entitlements. Select the scheme and an eligible iOS device destination, choose **Product → Archive**, then in Organizer validate the archive and choose **Distribute App → App Store Connect** to upload for an authorized submission. After processing, select that exact version and build. [Prepare for distribution](https://developer.apple.com/documentation/xcode/preparing-your-app-for-distribution)
4. For beta testing, assign the processed build to a TestFlight group and test on an iPhone. The first build of a version for external testers goes through TestFlight App Review. TestFlight is optional for App Store submission. Capture failures against the distributed build number. [TestFlight and beta review](https://developer.apple.com/help/glossary/)

## Prepare the review submission

| Area | Evidence to check |
| --- | --- |
| Completeness and reviewer access | Exercise the main flow on the release build with live backend services. Supply review contact, specific navigation steps, an active demo account and any sample inputs or hardware instructions required. Check guideline 2.1 for permitted demo-mode exceptions. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) |
| Functionality and listing | Under 4.2, evaluate what the app lets a person accomplish beyond a repackaged website. Use accurate screenshots, description, support and privacy URLs. Complete the age rating, availability and applicable export compliance answers. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) |
| Privacy and accounts | Match App Privacy disclosures to the release and its SDKs. Explain sensitive permissions in purpose strings. Check tracking consent, required-reason APIs, SDK manifests and signatures where applicable. If account creation is supported, provide account deletion within the app. [Review guideline 5.1](https://developer.apple.com/app-store/review/guidelines/#privacy) · [SDK requirements](https://developer.apple.com/support/third-party-SDK-requirements/) |
| Feature-specific rules | For digital purchases, check guideline 3.1 and storefront exceptions. For third-party login, check 4.8 and its exceptions. For user-generated content, check 1.2 on filtering, reporting, blocking and contact. Give reviewers a way to exercise the applicable features. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) |

In App Store Connect, attach the processed build to the app version, complete the metadata and select the release setting. **Add for Review** creates or updates a draft submission. **Submit for Review** sends it to Apple. Track review messages, address the cited guideline and upload a new build when the binary changes. Report submission, acceptance and public availability as separate outcomes. [Submit an app](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app/)
