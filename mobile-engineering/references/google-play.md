# Prepare a Google Play release

Use this workflow for an Android package, including React Native and TWA. Identify whether this is a first publication or an update, the account type, target devices and countries, and the permissions, payments, data flows and SDKs in the shipped variant. For an audit, report each applicable requirement with its evidence or the exact missing item.

## Build, test and submit

1. In Play Console, confirm the developer account is verified, the app record and application ID match, and the publisher has access to the intended track. Check any developer verification or package registration notices for the distribution region. [Android developer verification](https://developer.android.com/developer-verification)
2. In Android Studio, select the release variant and use **Build → Generate Signed Bundle / APK → Android App Bundle**, or the project's equivalent signed Gradle task. For an update, keep the registered package ID, use an unused higher version code and preserve signing continuity. For Play App Signing, sign the upload with the upload key. Play signs delivered APKs with the app-signing key. Check certificate-dependent features on a Play-delivered build. [Build for release](https://developer.android.com/build/build-for-release) · [App signing](https://developer.android.com/studio/publish/app-signing)
3. Check the target API for the release date and form factor. As checked on 2026-11-22, new phone apps and updates require Android 16 (API 36) or higher. Existing app availability and Wear, TV, XR and Automotive have separate rules. Check 16 KB page-size support for applicable 64-bit releases, including native libraries bundled by dependencies. [Target API requirements](https://support.google.com/googleplay/android-developer/answer/11926878) · [Page-size compatibility](https://developer.android.com/guide/practices/page-sizes)
4. Upload the AAB to the intended test track, install from the opt-in link and review the pre-launch report where available. Exercise the main action and an upgrade from the published version when applicable. Personal developer accounts created after November 13, 2023 currently need a **closed test with at least 12 testers continuously opted in for 14 days** before applying for production access. Keep actual feedback and changes for the application. Internal testing serves a separate purpose. [Testing eligibility](https://support.google.com/googleplay/android-developer/answer/14151465)
5. Complete the listing, screenshots, contact details, countries, pricing, release notes and applicable App content declarations. Review errors in the release preview. Use Publishing overview to send requested changes for review and check when approved changes will go live under the chosen publishing settings. Track approval and rollout separately. [Prepare for review](https://support.google.com/googleplay/android-developer/answer/9859455) · [Prepare and roll out a release](https://support.google.com/googleplay/android-developer/answer/9859348)

## What to check before review

| Applies when | Check against the release candidate |
| --- | --- |
| Every public submission | Launch and complete the advertised task with production services. Ensure the listing represents the actual build. Show meaningful, stable functionality, including in a TWA. [Functionality policy](https://support.google.com/googleplay/android-developer/answer/9898783) |
| Listing and privacy declarations | Publish the privacy policy in the app and listing. Reconcile Data safety answers with the app, third-party SDKs and hosted flows. Complete ads, target audience and content rating declarations. [App content](https://support.google.com/googleplay/android-developer/answer/9859455) |
| Restricted access or sensitive permissions | Supply working reviewer access and steps for gated features, including an accessible route past MFA. Check each sensitive permission against its user-facing purpose and complete applicable declaration forms. [Review access and permissions](https://support.google.com/googleplay/android-developer/answer/9859455) |
| Users can create accounts in the app | Offer account deletion requests inside the app and via an accessible external web resource. Enter its URL in Play Console and disclose any required retention. Test both entry points. [Account deletion](https://support.google.com/googleplay/android-developer/answer/13327111) |
| Digital purchases, subscriptions, children, ads or user-generated content | Determine the applicable payment and content policies for the business model and region. Trace a purchase or the relevant moderation, safety or consent flow. [Play policy center](https://play.google.com/about/developer-content-policy/) |
