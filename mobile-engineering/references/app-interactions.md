# Interaction patterns from 20 mobile apps

Use the flow that matches the user's task. The linked product documents describe the reference interactions. The implementation and checks below describe how to adapt each one to the target product. Use the project's terminology, visual language and navigation. In a brief naming several apps, identify which interaction each contributes.

## Learning, planning and operations

| Reference flow | How to implement the interaction | Check through the normal entry point |
| --- | --- | --- |
| **Duolingo** · Resume a learning path. [Learning path](https://blog.duolingo.com/add-new-course/) | Give each step a stable ID and a visible status. Make the next available step easy to find. Commit completion before advancing the path and let returning learners resume from the saved step. | Complete lesson two, leave and reopen. Lesson three is available and the screen reader identifies completed and current steps with sound off. |
| **Shopify** · Open an order from a notification. [Mobile admin](https://help.shopify.com/en/manual/shopify-admin/shopify-app) | Deep-link to the order ID, restore the correct store context and fetch its current status. Resume the intended destination after sign-in. If access has changed, offer a route to the orders list. | Tap an old notification after fulfillment. The detail shows the updated status and available actions. An account lacking access sees no order details. |
| **Nubank** · Save toward a named goal. [Caixinhas](https://nubank.com.br/nu/caixinhas) | Show the goal name beside its saved amount and, if set, its target. Use posted transactions as the balance source. Keep a pending contribution visibly pending. | Add to one of two similarly named goals. Only that goal changes after confirmation. Relaunch and reconcile the balance and history. |
| **Todoist** · Capture a task and date in one field. [Quick Add](https://www.todoist.com/pt-BR/help/todoist/features/use-task-quick-add-in-todoist-va4Lhpzz) | Echo a recognized date as an editable value before save. Support the user's locale and time zone, a manual date picker and a way to keep date-like wording in the title. | Type “Ligar amanhã às 16h” in Portuguese, correct the parsed date, then save. Reopen and confirm the intended title and local time. |

## Travel, delivery and offline use

| Reference flow | How to implement the interaction | Check through the normal entry point |
| --- | --- | --- |
| **Airbnb** · Save a place while exploring. [Saved places and itinerary](https://www.airbnb.com/help/article/4192) | Share saved-place IDs between map pins, result cards and the itinerary. Give Save its own state and label, separate from the booking action. Reconcile an optimistic save if the request fails. | Save on the map, find the same place in the itinerary, remove it and return. Both surfaces agree and no reservation has been created. |
| **Uber** · Identify the arriving vehicle. [Pickup identification](https://www.uber.com/br/pt-br/safety/uber-community-guidelines/keep-safe/) | At pickup, prioritize plate, vehicle model and driver identity. Expose the plate as readable text. Update these fields together when the assigned vehicle changes. | Simulate reassignment with the pickup screen open. The plate and driver belong to the same new assignment, including in the spoken description. |
| **iFood** · Follow an order through stages. [Order tracking](https://institucional.ifood.com.br/ajuda/como-funciona-a-entrega-do-ifood/) | Map fulfillment events to named stages. Display the current stage and the customer's next action. Order events by server revision or sequence and handle cancellation as a terminal state. | Deliver “out for delivery” followed by an older “preparing” event. The screen keeps the newer stage. Cancellation replaces the arrival estimate. |
| **Google Maps** · Download a selected area. [Offline maps](https://support.google.com/maps/answer/6291838?hl=pt-BR) | Preview the geographic boundary, estimated size and available space. Keep the region usable after its download completes and show its offline limits. | Interrupt a download and reopen. The partial area is identifiable. Complete it, disconnect, then try supported content inside and outside the boundary. |
| **Apple Wallet** · Present a boarding pass. [Using a pass](https://support.apple.com/pt-br/123179) | Put the pass identifier, departure and scannable code on the presentation screen. Show the local departure time and the last known details. Respect the issuer's validity and refresh rules for rotating codes. | Switch between two passes and verify each visible code belongs to the displayed trip. Try poor connectivity and distinguish a usable pass from one requiring refresh. |

## Capture, messaging and organization

| Reference flow | How to implement the interaction | Check through the normal entry point |
| --- | --- | --- |
| **Google Translate** · Translate text through a camera. [Image translation](https://support.google.com/translate/answer/6142483?hl=pt-BR) | Request the camera when capture starts. Keep source and target languages visible. Offer image import or typed text when live capture is unavailable. | Deny camera access, enter text manually, then switch the target language. The displayed result corresponds to the current input and language. |
| **Google Photos** · Act on the image being viewed. [Lens in Photos](https://support.google.com/photos/answer/7539151?hl=pt-BR) | Place the image action in its detail view. Bind any recognition result to the asset ID and revision that initiated it. Preserve the image and zoom context on dismissal. | Start recognition on A, swipe to B, then deliver A's result. B stays visible without an overlay belonging to A. |
| **WhatsApp** · Review a voice message before sending. [Voice drafts](https://blog.whatsapp.com/making-voice-messages-better) | Distinguish recording, paused draft, previewing, sending and sent. Play from the draft locally. Give discard and send separate labeled controls. | Record and preview twice. The recipient receives nothing until Send. Retry a failed send and verify only one message arrives. |
| **Signal** · Reply to a specific message. [Quoted replies](https://support.signal.org/hc/en-us/articles/6851465208986-Reply-to-a-specific-message) | Offer Reply in both a swipe gesture and an accessible action menu. Show the quoted author and excerpt in the composer. Store the parent message ID separately from the draft text. | Using the accessibility menu, quote one of two identical messages. Remove the quote and verify the typed reply remains editable. |
| **Pinterest** · Group saved items into sections. [Board sections](https://help.pinterest.com/en/article/create-a-board-section) | Allow a first save directly to a board. Offer optional sections and batch moves once a collection grows. Preserve item identity when its section changes. | Save three items without categorizing them. Move two into a section and rename it. Reopen the board and verify all three items remain, each in the intended place. |

## Playback, recommendations and activity

| Reference flow | How to implement the interaction | Check through the normal entry point |
| --- | --- | --- |
| **Spotify** · Inspect and edit the playback queue. [Play Queue](https://support.spotify.com/pg/article/play-queue/) | Keep one playback owner across the mini-player, full player and queue. Give each queued occurrence its own ID so the same track can appear twice. | Queue the same track twice, remove its second occurrence, then return to the player. Audio continues and the remaining queue order is correct. |
| **TikTok** · Give feedback on a recommendation. [Feed preferences](https://newsroom.tiktok.com/deixe-o-seu-feed-para-voce-mais-a-sua-cara?lang=pt-BR) | Attach “Not interested” to the item menu and offer an accessible alternative to long press. Bind the feedback to the item seen when the menu opened. Explain its effect in the product's own terms. | Open the menu on item A, refresh the feed, then submit feedback. Only A receives the preference event, even if its position changed. |
| **YouTube** · Seek by named chapter. [Video navigation](https://support.google.com/youtube/answer/12825599?hl=pt-BR) | Use timestamped chapter titles in the timeline and a selectable list. Derive the active chapter from playback position. Keep ordinary seeking available for videos without chapters. | Choose a middle chapter, seek backward across its boundary and check the active title. Repeat with a video that has no chapter data. |
| **Netflix** · Select audio description during playback. [Accessibility features](https://help.netflix.com/en/node/116022/) | List the audio tracks actually available for the title, with language and description labels. Apply a track change while preserving playback position. | Switch to audio description, resume at the same scene and open a title lacking that track. The selector accurately reflects both titles. |
| **Strava** · Record an activity while in motion. [Activity recording](https://support.strava.com/en-us/articles/15402137-how-do-i-record-an-activity-on-strava) | Separate recording, paused, finished and pending upload. Use optional audio cues and a persistent visual status. Save the session locally before syncing it. | Pause, lock and unlock the phone, resume, then finish offline. Paused time stays excluded from the active timer and reconnecting produces one saved activity. |
| **Shazam** · Identify music with one action. [Music recognition and history](https://support.apple.com/pt-br/118557) | Put recognition on the primary control. Show listening, cancellation, match and no-match states. Keep successful results in history so the user can act on them later. | Start and cancel, then start again. Deliver the first attempt's late result and a match from the second. Only the active attempt adds a new history entry. |
